# Как написать концепт плашки

Папка: `design/glass` в репозитории VoiceTyper. Обзор лаборатории — `README.md`, план следующего
круга — `NEXT.md`.

Концепт — один файл `<id>.js` в этой папке. Он вызывает `LG.register({...})`.
Основа (`harness.js`) даёт холст WebGL2, сцену «за стеклом», состояния, голос,
текст плашки, пружины и GLSL-заготовки. Не меняй `harness.js`, `stage.css`,
`index.html`, `solo.html`, `shoot.py` и чужие концепты — только свой файл.

## Регистрация

```js
LG.register({
  id: 'lens',                 // совпадает с именем файла
  setup(ctx) {                // один раз: собрать шейдеры, завести пружины
    this.prog = ctx.program(ctx.glsl.header + ctx.glsl.common + SHAPE + ctx.glsl.glass + MAIN);
    this.w = new ctx.Spring(260, 0.45, 0.72);   // value, response (с), dampingFraction
  },
  frame(ctx, s) {             // каждый кадр
    ctx.draw(this.prog, { uCenter: [ctx.W / 2, ctx.H / 2], uSize: [w, h], uLevel: s.level });
    return { cx, cy, labelOpacity, labelScale, labelColor, iconColor, labelBlur, hideLabel };
  },
});
```

`ctx`: `gl` (WebGL2), `canvas`, `W`, `H` (CSS px), `dpr`, `program(fragSrc[, vertSrc])` →
`{prog, uniforms}`, `draw(program, uniforms)` — ставит общие юниформы, привязывает
текстуру сцены к юниту 0 и рисует полноэкранный треугольник; юниформы-числа и массивы
длины 2–4 ставятся по имени. `ctx.Spring` — пружина (`set(target)`, `step(dt)`,
`snap(v)`, поля `value`, `velocity`). Нужны свои текстуры или кадровые буферы —
заводи через `ctx.gl`, но помни, что `draw` использует юнит 0 для сцены.

`s` (снимок состояния на кадр):
- `stage`: `listening | transcribing | polishing | done | error | hidden`; `prev` — прошлое
- `t` — секунд в текущем состоянии; `time` — общее время; `dt`
- `level` — громкость 0..1 (сглажена: атака ~25 мс, спад ~140 мс), `raw` — без сглаживания,
  `history` — Float32Array(96) последних уровней, `bands` — Float32Array(5) «полос»
- `text` — `{title, detail}`; `targetW` — ширина плашки под этот текст, px (210–640)
- `accent` — цвет стадии `[r,g,b]` 0..1, `accentHex`; `shown` — `stage !== 'hidden'`

Цвета стадий: слушаю `#ff5f6d`, распознаю `#79b0ff`, причёсываю `#b79cff`, готово `#4fdca6`,
ошибка `#ff6b74`. Высота плашки ~56 px, центр по умолчанию — центр холста.

Возврат `frame` управляет HTML-текстом поверх холста (иконка + заголовок + деталь):
`cx, cy` — центр текста в CSS px холста; `labelOpacity` 0..1; `labelScale`; `labelColor`
— `'light' | 'dark' | css-цвет` (по умолчанию выбирается по светлоте фона под плашкой);
`iconColor`; `labelBlur` (px, для перетекания текста); `hideLabel: true` — если рисуешь
текст сам. Текст должен двигаться вместе с формой и не вылезать за неё.

## GLSL

`ctx.glsl.header` — `#version 300 es`, юниформы `uScene, uRes, uDpr, uSceneSize, uSceneOff,
uSceneScale, uTime` и `out vec4 outColor`. Свои юниформы объявляй сам.

`ctx.glsl.common`:
- `vec2 cssCoord(gl_FragCoord.xy)` — CSS px, начало слева сверху (y вниз)
- `vec3 sceneAt(vec2 p, float lod)` — фон в точке; `vec3 sceneBlur(vec2 p, float r)` — размытый фон, r в px
- `sdRoundBox, sdPill(p, center, w, h), sdCircle`, `hash21, vnoise, fbm`, `luma`
- `smin(a, b, k)` — НОРМИРОВАННЫЙ квартичный гладкий минимум: k = наибольшее вздутие в px.
  Мостик между фигурами живёт при зазоре ≤ 2k, влияние начинается с 5.33k. Для капсулы 56 px:
  k в покое 5.25, в движении 7–8 (k(t) = 5.25·(1 + 0.4·m), m = 1 пока идёт пружина), НИКОГДА > 10
  (иначе форма «ватная»). Неактивную каплю убирай из smin множителем k·presence, иначе она
  раздувает капсулу изнутри. Порядок цепочки smin фиксированный: капсула, потом капли. `smax`.

`ctx.glsl.glass` — общее жидкое стекло, откалиброванное по нативному Apple (см. ниже).
ПЕРЕД ним определи `float shape(vec2 p)` — SDF формы в CSS px (минус внутри). Он же объявляет
`uniform float uRefraction` (не объявляй его сам). Даёт:
- `struct Glass`: `bevel` (h, ~13 px), `amplitude` (A, ~41 px), `dispersion` (0), `frost` (σ ~2.4),
  `gain, lift` (1.015, +0.086), `tint, tintAmount`, `highlight` (1), `light` (направление на свет),
  `darkRim` (1 — тёмная кромка iOS 27), `shadow, shadowBlur, shadowY` (0.035, 30, 8), `materialize` (0..1)
- `Glass defaultGlass()`, `float shapeDist(p, out vec2 n)` — нормированное расстояние и внешняя
  нормаль, `vec2 shapeNormal(p)`, `vec4 liquidGlass(p, g, bg)` — rgb поверх фона, a — покрытие.

Как устроено стекло Apple (замер нативного iOS 26 попиксельно, подробности в RESEARCH.md):
у кромки фон берётся ВНУТРЬ по нормали: `src = p − n·A·(1 − √(1 − t²))`, `t = 1 − dist/h`.
A больше h и даже больше радиуса торца, поэтому кромка «зеркальная»: верхний край показывает
перевёрнутый и сжатый контент из глубины, как стеклянный стержень. Центр 1:1, без лупы. Лёгкое
размытие σ ≈ 1.8–3 px и подъём яркости ~+8.6%, насыщенность не трогается. Блик — жёсткая полоса
1 px цвета самого контента через vibrant-матрицу, от двух источников с противоположных углов,
а не белая обводка. Тени почти нет; в iOS 27 — тёмная кромка, толще на торцах. Появление —
«материализация»: растёт линза (A, блик, размытие, подъём), а не прозрачность. Когда стекло
становится больше, оно «толще»: h и A растут примерно как размер^0.3.

`uRefraction` и `s.refraction`: переключатель на странице «Линза: как у Apple / как в композиторе
Windows». При 0 смещения фона нет (так умеет композитор Windows без внедрения в DWM). Если в твоём
концепте есть своё смещение фона (волны, капли-линзы), умножай его на `uRefraction` тоже.
Можно не пользоваться общим стеклом и написать своё, если концепт этого требует, но планка та же.

Сжатая выжимка исследования — `RESEARCH.md`: числа и проверенные ссылки. Сырой отчёт лежит рядом
в `research.json` — только на этой машине, в git не идёт (≈600 КБ JSON: `research[]` по темам apple,
web, morph, voice, windows и `fills[]` с уточнениями: эталон оптики в числах, нормировка smin, рецепт
текста в «Готово», Material 3 Expressive). Ищи в нём по ключевым словам (grep/Python), читай
techniques и principles — там формулы, параметры и ссылки.

Производительность: пиксели далеко от формы должны почти ничего не стоить (сначала
расстояние, потом дорогие выборки). Бюджет — плавные 60 к/с на средней видеокарте.

## Проверка

```
python shoot.py <id> [стадия/фон/мс[/flat] ...]
```
`/flat` в конце — снимок в режиме «как в композиторе Windows» (без смещения фона).
Без списка снимает набор: слушаю над кодом и документом, распознаю над обоями, готово над
обоями и документом, ошибка над кодом. `мс` — сколько миллисекунд страница живёт до снимка
(одна и та же стадия в разные моменты показывает движение). Снимки: `shots/<id>/*.png` —
открывай их инструментом Read и смотри глазами. Ошибка шейдера видна прямо на снимке
красным текстом и в выводе скрипта.

## Планка

Текст: сплошной, резкий, не преломляется и не деформируется; перетекает только прозрачностью
и коротким размытием (до 300 мс) на появлении и уходе. Контраст 4.5:1 добирается выбором
светлого/тёмного текста и ореолом под буквами (это делает основа), а не заливкой всего стекла.
Текст обязан влезать в форму на всех кадрах морфа.

Заказчик отверг «тонировку»: плашка, где фон почти не виден, — провал. Стекло — это когда
фон виден насквозь, у кромки ломается и слегка расходится на цвета, есть тонкий блик со
стороны света и слабый напротив, тень едва заметна. Тонировка минимальная; читаемость
текста — за счёт выбора светлого/тёмного текста и лёгкой подложки только под текстом, если
иначе никак. Движение — пружины и перетекание, без механических линейных анимаций, без
спиннеров и бегущих по кругу комет. Одно главное движение в кадре, остальное — тише.
