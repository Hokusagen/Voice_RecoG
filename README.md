# VoiceTyper

Голосовой ввод для Windows и macOS: зажали клавишу, продиктовали, отпустили —
текст появился в активном окне уже причёсанным.

Речь распознаёт [faster-whisper](https://github.com/SYSTRAN/faster-whisper)
локально на видеокарте, черновик вычищает локальная модель через
[Ollama](https://ollama.com). В таком виде ничего никуда не отправляется.
Есть и лёгкий вариант: без локальных моделей, распознавание и правка в облаке.

## Как это выглядит

Вместо системных уведомлений — плашка из жидкого стекла внизу экрана, по
замерам Apple Liquid Glass: середина прозрачная, кромка, как у линзы, берёт фон
изнутри и показывает его перевёрнутым, сверху ложится тонкий блик цвета того,
что под стеклом. Плашка появляется ростом линзы, а не прозрачностью, а при каждой
смене состояния свет один раз обходит её силуэт.

| Состояние | Форма | Знак |
|---|---|---|
| Загружаю модель | капсула с подписью, стекло медленно дышит | дышащая точка |
| Слушаю | капсула без надписей; голос — пласты цветного света внутри стекла | — |
| Распознаю, причёсываю | капсула стягивается в прозрачный диск, он перетекает между формами | — |
| Готово после диктовки | диск; полоса внутри кромки вспыхивает и стягивается в зелёный | галочка прорисовывается штрихом |
| Готово, служебное | капсула с подписью и зелёной вспышкой | галочка |
| Ошибка | капсула встряхивается, красная вспышка | крестик |

На плашке только заголовок, без пояснений мелким текстом. Итог диктовки она не
повторяет: текст уже вставлен под курсор, плашка лишь отмечает галочкой, что
всё прошло. Цвет — в итогах и в голосе: пока вы говорите, снизу стекла
поднимаются пласты синего, фиолетового и розового света, в паузе они оседают
в тонкую бледную полосу.
Посмотреть голос со своего микрофона: `python src/demo.py voice`.

Она прозрачна для мыши и не забирает фокус, так что Ctrl+V попадает туда, куда
вы диктуете. Иконка в трее — тот же язык: форма микрофона не меняется, меняется
цвет, а работу показывает медленное дыхание прозрачностью.

Посмотреть оформление, ничего не диктуя:

```bash
venv\Scripts\python.exe src\demo.py
```

### Про стекло

Плашка собрана из двух слоёв ([src/ui/lens_hud.py](src/ui/lens_hud.py)). Середину
рисует системный композитор Windows из живого фона — в том же кадре, что и весь
экран, поэтому при прокрутке она не отстаёт ни на пиксель. Кромку, тень, блик,
значок и подпись рисует шейдер Direct3D 11
([src/ui/lens_shader.py](src/ui/lens_shader.py)) по снимку экрана: снимок
запаздывает на кадр-два, но у кромки фон перевёрнут и сжат, продолжения снаружи
у него нет, и запоздание видно разве что на рывках колеса мыши. Пока форма
движется, шейдер рисует стекло целиком, середину композитору отдаёт в покое.

Чтобы шейдер не снимал сам себя, плашка исключена из захвата экрана — из-за
этого её не видно в OBS, Zoom и записях экрана.

Тон подписи выбирается по светимости фона: над светлым документом тёмный текст
с белым ореолом, над тёмным окном — светлый с тёмным.

Где композиции нет (macOS, Windows старше 10 1809, ключ `ui.lens_glass: false`),
работает прежняя плашка: стекло, которое обсчитывает Python
([src/ui/liquid.py](src/ui/liquid.py), [src/ui/live.py](src/ui/live.py)), и
свечение по кромке. Как подбиралось стекло — `design/glass`.

### Про шрифт

По умолчанию — **Segoe UI**, и это не лень. Он вручную отхинтован под мелкие
кегли Windows, поэтому на 12–14 пикселях штрихи попадают ровно в пиксельную
сетку. Inter, Onest, Golos Text и Manrope инструкций хинтинга не несут и на тех
же кеглях расползаются — проверено рендером всех четырёх от 11 до 15 пикселей.

Все четыре всё равно лежат в [assets/fonts](assets/fonts) и включаются ключом
`ui.font` в конфиге: на экране с крупным масштабом они могут зайти лучше.

## Установка

### Готовые сборки

На странице [Releases](../../releases) к каждой версии лежат четыре архива.
Распакуйте и запустите `VoiceTyper` (на macOS — `VoiceTyper.app`).

| Архив | Что внутри | Кому |
|---|---|---|
| `windows-full` | Whisper на видеокарте NVIDIA или процессоре, правка через Ollama или облако; около 2 ГБ | Хочется работать без сети и никуда не отправлять речь |
| `windows-lite` | Только облако: и распознавание, и правка; около 150 МБ | Нет видеокарты или места, есть ключ Groq |
| `macos-full` | Whisper на процессоре, правка через Ollama или облако | Mac без сети |
| `macos-lite` | Только облако | Mac, нужна скорость и минимум места |

Лёгкой сборке обязателен ключ облака: без `cloud.api_key` в настройках она
честно скажет об этом на старте. Полная работает и без ключа, а с ключом умеет
всё то же, что лёгкая. Ollama и модели в архивы не входят — см. ниже.

На macOS при первом запуске система спросит три разрешения: микрофон,
«Универсальный доступ» (для горячих клавиш и вставки) и «Запись экрана» (для
стекла под плашкой; без него плашка будет непрозрачной, всё остальное
работает). Приложение не подписано, поэтому первый раз открывать через правый
клик → «Открыть».

### Из исходников

Нужен Python 3.11+ и микрофон.

```bash
python -m venv venv && venv\Scripts\activate && pip install -r requirements.txt
```

На macOS вместо `venv\Scripts\activate` — `source venv/bin/activate`. Для лёгкого
варианта без локальных моделей — `pip install -r requirements-lite.txt`.

Для работы на видеокарте NVIDIA больше ничего не требуется — CUDA-библиотеки
приезжают пакетами `nvidia-*` из `requirements.txt`. Без видеокарты приложение
само переключится на процессор.

Постобработку текста включает Ollama:

```bash
ollama pull qwen2.5:3b
```

Без неё всё продолжит работать — просто вставится сырой текст Whisper.

## Запуск

```bash
venv\Scripts\python.exe src\main.py
```

Приложение живёт в трее. Первый запуск скачивает модель распознавания
(`large-v3-turbo`, около 1.6 ГБ) — плашка честно об этом предупредит.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `F8` | Диктовать: распознать и причесать моделью (стиль выбирается в трее) |
| `Shift+F8` | То же, но в другом стиле: сухом, если по `F8` бережный, и наоборот |
| `Ctrl+F8` | Быстро: вставить сырой текст, не дожидаясь Ollama |
| `Ctrl+Shift+F8` | Запомнить правку: выделить исправленный текст и нажать |
| `Alt+F8` | Спросить Дарви: вопрос голосом, ответ в текст не вставляется |
| `Esc` | Отменить активную запись |

Стилей правки два. Бережный убирает слова-паразиты и расставляет знаки, но
оставляет каждое осмысленное слово на месте. Сухой снимает всё разговорное и
оставляет только суть — так удобно диктовать задания и промпты. Какой из них
висит на `F8`, выбирается в меню трея «Правка по F8»; второй всегда на
`Shift+F8`.

В меню трея переключается режим клавиши: удерживать (по умолчанию) или
нажать один раз для старта и второй для остановки. Меню открывается и левым,
и правым кликом по иконке.

### Запомнить правку

Диктовка проходит через две модели, и ошибиться может каждая: Whisper —
расслышав, редактор — исправив. Кто именно ошибся, приложение не знает: оно не
знает, как было сказано на самом деле. Знаете вы — и правите текст прямо там,
куда он вставился.

Поправили — выделите исправленное предложение и нажмите `Ctrl+Shift+F8`.
Приложение само скопирует выделенное, найдёт, из какой диктовки оно выросло, и
допишет в журнал одни различия. Буфер обмена вернётся таким, каким был. Ничего
подтверждать не нужно: если править нечего, нажимать не нужно и клавишу.

Выделяйте предложение целиком, а не одно слово: по одному слову, да ещё и
исправленному, найти диктовку не по чему — приложение так и скажет. Выделенное,
которое ни на что не похоже, никуда не пишется.

Что из этого выросло, показывает `python src/journal_report.py`: раздел «Правки
руками» собирает слова, которые пришлось исправлять, и раскладывает их на две
кучки — не расслышал Whisper или испортил редактор.

### Спросить Дарви

`Alt+F8` — вопрос, а не диктовка: текст Whisper уходит языковой модели, и её
ответ ничего не вставляет в активное окно. Своя клавиша, а не догадка модели,
нарочно: вопрос, надиктованный в чат, должен вставиться, а не получить ответ.
Пока карточка с ответом открыта, та же клавиша задаёт уточнение в том же
разговоре, и модель видит прошлые вопросы и ответы. Для распознавания
уточнения Whisper получает подсказкой начало прошлого ответа: термины из него
человек скорее всего повторит.

Ответ приходит в карточку в углу экрана (`ui.card_corner`, по умолчанию
справа снизу). Она появляется с первым словом и растёт вслед за текстом, а
фокус не забирает: работа в своём окне продолжается, кнопки нажимаются мышью.
В карточке весь разговор: первый вопрос — в шапке, уточнения с ответами —
ниже одной лентой. Уточнение встаёт в ленту, как только распознано; длинная
лента листается, и новый вопрос держится у её верхнего края, пока не
прокрутишь сам. Ширину карточки меняют, потянув мышью за свободный край, как
у обычного окна; она запоминается в `ui.card_width`.

Кнопки — у последнего ответа: «Вставить» отправляет его туда, где стоит
курсор, «Копировать» кладёт в буфер, «Проверить в интернете» задаёт последний
вопрос заново с поиском и подписывает ответ источниками. Крестик заканчивает
разговор — следующий вопрос начнёт новый. Начатая диктовка карточку только
убирает: вопрос в пределах пяти минут после ответа (`ask.followup_s`)
продолжит разговор и вернёт карточку со всей лентой. Почему карточка такая,
записано в `design/DARVI-SKILLS.md`; посмотреть её без облака и микрофона —
`python src/demo.py card`.

Каждый вопрос пишется в журнал диктовок записью вида `ask`: вопрос, ответ,
модель, искала ли она в интернете и где, время до первого слова и до конца,
токены раздумий. Запись самого вопроса ложится в `asks` рядом с журналом
(`ask.keep_audio`, последние двести): без звука распознавание потом не
перемерить.

Искать в интернете перед каждым ответом умеет встроенный поиск gpt-oss у Groq
(`ask.web_search`), но по умолчанию он выключен: по замеру поиск обходится
впятеро дороже по токенам и втрое по времени, и бесплатного суточного запаса
с ним хватает примерно на 40 вопросов вместо 230. Поэтому ищем по просьбе —
кнопкой в карточке. В `ask.about` можно коротко написать о себе, например
систему и версии библиотек, — ответы про код и настройки будут для них.

Отвечает облако — по умолчанию тот же сервер, что у правки, модель своя
(`ask.model`, `ask.reasoning_effort`): у Groq лимиты считаются на модель, и
вопросы не отнимают у правки ни запросов, ни токенов. Свой сервер для вопросов
задаётся в `ask.url` и `ask.api_key` — подойдёт любой OpenAI-совместимый с
потоковым ответом.

Какой сервер и модель отвечают лучше, решает слепой замер на своих вопросах:

```bash
python src/ask_eval.py questions   # набор вопросов из журнала — почистить руками
python src/ask_eval.py run         # прогнать через кандидатов из candidates.json
python src/ask_eval.py report      # страница для оценки, кандидаты под буквами
```

Всё это лежит в `%APPDATA%\VoiceTyper\ask_eval`, включая ключи чужих серверов
в `candidates.json`, и в репозиторий не попадает.

### Облако

Локальные модели, которые влезают в 4 ГБ, чистят мусор, но сухой стиль им не
даётся. Для него есть облако: любой OpenAI-совместимый сервер, по умолчанию
Groq — бесплатный тариф без карты, тысяча правок и восемь часов аудио в сутки,
на данных не обучают. Ключ с console.groq.com вставляется в `cloud.api_key`,
после чего в трее в меню «Редактор» появляется выбор: локально или в облаке.
Пока правит облако, Ollama не занимает видеопамять; если облако не ответило,
правка уходит в Ollama, а без неё вставляется сырой текст с предупреждением.
Бесплатный тариф Groq ограничен восемью тысячами токенов в минуту, это
пять-шесть диктовок подряд, и тысячей правок в сутки. Остатки видны в меню
трея под строкой состояния и пишутся в журнал. Перед каждой правкой
приложение сверяется с ними: если минутного лимита на фразу не хватает и
сброс через пару секунд — ждёт, если дальше или кончились суточные запросы —
сразу отдаёт правку Ollama. За полсотни оставшихся правок плашка предупредит,
а когда лимит восстановится — сообщит «Лимит по токенам в минуту восстановлен».

У облака есть запасной выход. Groq закрывает доступ не по ключу, а по адресу,
и закрывает целыми диапазонами: в одно утро он ответил «Access denied» на
каждый запрос — с рабочим ключом, просто потому, что VPN выходил в сеть через
разлюбившийся ему диапазон. Правка в такие минуты уходит в Ollama, а вот
распознавание при отданной видеокарте сваливается на процессор, где идёт в
реальном времени: шестнадцать секунд речи — шестнадцать секунд ожидания.
Поэтому в настройках есть второй сервер, `cloud.reserve`. Если в нём стоит
ключ, приложение уходит туда само — на отказ по сети, на закрытый доступ, на
серверную ошибку, а в распознавании ещё и на исчерпанный лимит, — и плашка
предупреждает, что работает запасное облако. Через четверть часа основное
пробуется снова, и когда оно отвечает, всё возвращается на бесплатный тариф.
По умолчанию там OpenRouter: те же пути, те же модели, что просим у Groq,
оплата с баланса, включая крипту. Стоит это копейки — доли цента за правку и
около цента за час аудио, — но тариф платный, и потому ключ вставляется руками.

Если Groq закрыл доступ с адреса VPN, а менять VPN не хочется, обойти это
можно бесплатно и без второго сервера — через Cloudflare AI Gateway. VPN и
датацентры Groq режет как защиту от мошенничества, даже собственные Workers
Cloudflare, но запросы официального шлюза пропускает. Шлюз заводится на
dash.cloudflare.com в разделе AI → AI Gateway, и его адрес с хвостом `/groq`
встаёт в `cloud.url` вместо адреса Groq:

```
https://gateway.ai.cloudflare.com/v1/<account_id>/<имя шлюза>/groq
```

Ключ, модели и бесплатный тариф остаются прежними, через шлюз проходят и
правка, и распознавание, а остатки лимитов по-прежнему видны в трее. Галочку
Authenticated Gateway в настройках шлюза оставьте выключенной: этого заголовка
приложение не шлёт. Логи шлюз собирает по умолчанию, и в них копятся тексты
диктовок — их лучше выключить там же. Посторонних в цепочке при этом не
прибавляется: Groq и так стоит за Cloudflare.

Всё, что диктуется с включённым облаком, уходит на его сервер. Если для
рабочих диктовок это неприемлемо, оставьте редактор локальным.

### Отдать видеокарту

Whisper и Ollama вместе занимают около 3.5 ГБ видеопамяти. Когда она нужна
другой задаче — обучению модели, рендеру, — пункт трея «Отдать видеокарту»
выгружает редактор и переселяет Whisper на процессор. Диктовка продолжает
работать. С ключом облака распознавание тоже уходит туда и занимает секунду;
без ключа — на процессор, где turbo распознаёт в реальном времени. Правка в
этом режиме есть только облачная. Снятие галочки возвращает всё на
видеокарту за десяток секунд. Состояние запоминается между запусками.

## Настройки

Всё правится в `%APPDATA%\VoiceTyper\config.json` — файл создаётся и
открывается пунктом «Открыть настройки» в меню трея. Изменения подхватываются
при следующем запуске.

Сам по себе файл не появляется намеренно: записанные при первом запуске
умолчания потом перекрывали бы новые, и обновление приложения не меняло бы
ничего.

Что чаще всего хочется поменять:

| Ключ | Смысл |
|---|---|
| `hotkeys.record` | Основная клавиша |
| `hotkeys.correct` | Клавиша «запомнить правку»; пустая строка — выключить |
| `whisper.model` | `large-v3-turbo`, `medium`, `small` — компромисс точность / память |
| `whisper.compute_type` | `int8_float16` экономит вдвое видеопамяти против `float16` |
| `whisper.initial_prompt` | Термины вашей предметной области через запятую — Whisper распознает их точнее. По умолчанию пусто: заполняйте, только если правда их диктуете, — на тишине в конце записи Whisper иногда договаривает подсказку прямо в текст |
| `llm.enabled` | Выключить постобработку целиком |
| `llm.journal` | Журнал диктовок в `dictations.jsonl`: сырой текст, попытки правки, тайминги, приложение-получатель и качество записи. Сводка — `python src/journal_report.py` |
| `llm.system_prompt` | Правила бережной правки |

## Ярлык на своей машине

Собранный `.exe` устаревает ровно тогда, когда меняется исходник, и
закреплённая на панели задач иконка продолжает молча запускать позавчерашнюю
сборку. Поэтому на своей машине ярлык лучше вести не на `.exe`, а на исходники:

```bash
python shortcut.py --pin
```

Скрипт рисует `assets/voicetyper.ico` (тот же микрофон, что в трее), кладёт
`VoiceTyper.lnk` в каталог проекта и с `--pin` перенацеливает уже закреплённый
на панели задач ярлык на `venv\Scripts\pythonw.exe src\main.py`. После этого
пересобирать ради своих запусков не нужно вообще: ярлык поднимает то, что
лежит в каталоге сейчас. Вернуть всё на сборку — `python shortcut.py --exe --pin`.
Консоли у pythonw нет, поэтому вывод идёт туда же, куда у сборки, — в
`voicetyper.log` рядом с настройками.

Пересобирать по-прежнему нужно для чужой машины — там нет ни Python, ни venv.

## Сборка

```bash
python build.py
```

Скрипт закрывает работающее приложение — иначе PyInstaller не перезапишет
занятый `.exe`, — собирает и поднимает его обратно. `--yes` пропускает вопрос,
`--no-run` оставляет приложение закрытым, `--lite` собирает лёгкий вариант в
`dist\VoiceTyper-lite\`.

Готовое приложение — в `dist\VoiceTyper\`; под капотом всё та же команда
`venv\Scripts\pyinstaller.exe VoiceTyper.spec`. Переменная `VOICETYPER_LITE=1`
переключает spec на лёгкий вариант, на macOS он же собирает `.app`.

Релизы собирает GitHub Actions: тег `v0.5.0` на коммите с той же версией в
`src/config.py` запускает сборку всех четырёх архивов и выкладывает их в
Releases с заметками из `CHANGELOG.md`. Проверка импорта на Windows и macOS
идёт на каждый пуш.

Номеров два, и путать их не надо:

- `APP_VERSION` в `src/config.py` — релизный, поднимается руками вместе с
  записью в [CHANGELOG.md](CHANGELOG.md) и тегом, по которому идёт сборка;
- `build_version()` — то, что реально запущено: `0.7.0+27.be61a8c`. Хвост
  берётся у git и меняется сам с каждым коммитом, суффикс `.dirty` значит, что
  поверх коммита лежат несохранённые правки. Он и виден в подсказке трея и в
  каждой записи журнала, так что по ним всегда понятно, какой именно код
  работал. В собранном приложении git недоступен, поэтому `build.py`
  впечатывает посчитанный номер во временный `src/_build.py`.
